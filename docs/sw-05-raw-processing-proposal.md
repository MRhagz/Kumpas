### Evidence and limitations of the previous approach

- **Reported by the requester:** earlier local recognition missed identifiers. The failed samples, engine/configuration, identifier recall, and reproducible benchmark were not supplied. This is a reason to investigate the architecture, not a measured result of this PR or proof that every application-hosted model will fail.
- **Recorded historical rationale:** the [Module 2 report, deviation 6](superpowers/reports/2026-05-23-module-2-implementation-report.md#4-stated-deviations-from-sdd--srs) says a team evaluation favored Gemini over Tesseract.js on Philippine documents. Its assertion of a paid-tier no-retention guarantee is not accepted as current provider evidence. No independently reproducible comparison is established here.
- **Source-observed on current main:** `src/lib/module2/pii-redaction-service.ts` sends raw image bytes to the Developer API and returns identifier text with coordinates; an empty region list passes the image through. The session upload calls it before extraction. The legacy document and note-photo extraction routes send raw content directly. Note review does not replace masking. These paths remain unchanged and do not satisfy the original SW-05 boundary.
- **Engineering inference:** a detector can miss an identifier without signaling uncertainty. A successful request, an empty region list, or a high recognition score cannot alone prove safe release. Switching providers does not establish perfect masking; false negatives remain an explicit risk to test and review.

## Proposed processing flow and release gates

1. Authenticate the invited counselor and authorize the owned, valid session where applicable. Validate actual content, supported type, size and input category before any model call. Preserve SW-03's contract; exclude original filenames and identifiers from diagnostics.
2. Keep raw image/PDF processing within the current bounded invocation. Process all pages in order, without sending raw PDFs, embedded text layers, metadata or local paths to another function. Any derived page raster containing identifiers is raw data. Do not silently drop pages or accept unreadable rendering as success.
3. Before raw transmission, verify the approved configuration and evidence reference. Only the designated Vertex project, location, model and masking operation may receive raw page images over authenticated HTTPS. Disable redirects or alternate-provider fallbacks that could bypass the recipient restriction. Ask only for mask geometry/categories, not transcription or academic/note extraction.
4. Validate page association and geometry, apply opaque masks in the application, and re-encode images without hidden text, original metadata or recoverable covered pixels. Incomplete pages, malformed/out-of-bounds geometry, suspiciously empty results, unreadable inputs and unresolved masking uncertainty block release. An empty result is not automatic clearance. The later implementation must demonstrate its clearance rules on the agreed fixtures before approval for live use.
5. On success or failure, run RawImagePurger in the same invocation. Clear owned raw buffers and temporary copies; confirm temporary-file absence. On cleanup failure, discard/deny the candidate output and retain only the minimal operation reference required for monitored retry. Never recover by handing another invocation a raw local path. Document runtime-specific limits: unlinking a file and clearing application-owned buffers do not prove physical storage erasure or removal of every managed-runtime copy.
6. Only after masking and application cleanup succeed may REDACTION_COMPLETE authorize redacted storage or structured extraction. Release all pages atomically for the affected document. Apply this to session uploads, the legacy academic endpoint and note-photo extraction; no direct raw extraction exception exists. Preserve old successful academic values on a failed replacement and offer recoverable Retry, Replace or Remove actions.
7. Keep extracted notes editable in the existing five fields. Require Career Goal and Personal Interests and Strengths, allow an undecided goal and blank optional fields, and retain review invalidation after edits. No confidential narratives or identifiers belong in downstream prompts or academic correction logs. Counselor review after extraction cannot undo an earlier raw disclosure.

### Zero content retention condition

For this proposal, zero content retention means that the masking processor retains no uploaded page, prompt content, output, or content-derived cache after processing the request. Inventory any retained operational metadata separately and verify it contains no student content. This is the proposed acceptance definition, not a statement that Google's standard terms promise it.

Approval needs the actual agreement and technical evidence for the exact model and features, including abuse-monitoring logs, human review, implicit/explicit caches, request/response logs, stateful APIs, backups, support copies and applicable legal exceptions. Do not equate no training, no durable caching, application deletion, or provider-defined "ZDR" with this stricter condition. If any applicable exception permits content retention, or evidence cannot resolve it, the condition remains unmet. Revising it requires a new explicit baseline decision; there is no automatic bounded-retention fallback.

No project, model version, region, contract exemption or zero-retention eligibility is approved by this PR. Until the approval record is complete and the follow-up controls are verified, real-record cloud masking remains unauthorized. This document adds no enforcement to the currently nonconformant runtime.

## Follow-up verification specification

**All tests below are proposed and not executed by this documentation PR.** They would replace or extend the approved tests only after the baseline owners approve the change.

Cover JPEG, PNG, WEBP and academic PDFs; typed/handwritten identifiers, repeated identifiers, clean/low-quality/non-standard layouts, multipage/mixed-quality cases and absent/unreadable fields. Record seed strings, variants, page numbers and mask coordinates, plus expected academic values and five-field notes. Include representative reproductions of the reported misses if supplied. Use no real student records.

Intercept every outbound transport, including retries/redirects, with synthetic provider boundaries. Parse payloads and decode attached images. JSON/base64 substring search alone cannot detect visible identifiers in pixels: compare each annotated identifier region in decoded output against an independent image/mask oracle and inspect residual text layers/metadata.
